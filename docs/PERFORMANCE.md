# VUS 性能优化专项记录

> 版本：v3.0.20260904150204（正式版）
> 范围：编译器速度、生成代码质量、运行时核心库 `libvus_rt` 性能。
> 基准工具位于 `.bench/`（`big.vus` 大文件编译基准、`hot.vus`/`hot2.vus` 热循环运行基准）。

## 一、优化总览与收益

| 指标 | 优化前 | 优化后 | 提升 |
|------|-------:|-------:|------|
| 210KB 源生成 C 代码体积 | ≈ 2.10 MB | ≈ 1.15 MB | **−45%** |
| 大文件 `vus build --exe` 编译耗时 | ≈ 14.3 s | ≈ 10.2 s | **−29%** |
| 热循环运行耗时（`hot2.vus`，50×50000 迭代，10⁷ 级加法/赋值） | ≈ 1.67 s | ≈ 0.88 s | **+47%** |

三层优化的关系：生成代码越紧凑 → GCC 解析/优化负担越低 → 编译越快（−29% 主要来源）；运行时热路径（字符串构造、变量赋值、数值转文本）越短 → 解释型语义下的执行越快（+47% 主要来源）。

## 二、生成代码优化（`src/generator.c`）

### 2.1 函数体特征扫描（按需生成变量与模板）

- 改动前：每个函数固定生成 `_vus_err`、`_vus_result` 变量及对应错误链/返回值模板，即使函数**没有** `返回`、**没有** `尝试/捕获`。
- 改动后：在生成前扫一遍函数体（`gen_*` 遍历 `VusAstFunctionDef` 语句），按特征**按需生成**：
  - 出现 `返回` → 生成 `_vus_result` 与返回模板；
  - 出现 `尝试`/`抛出` → 生成 `_vus_err` 与错误链模板。
- 收益：无返回/无异常的函数（如初始化、纯副作用函数）体积显著下降，大文件中此类函数占多数。

### 2.2 变量赋值热路径 `vus_var_set`

- 改动前：`x = 值` 生成 3~5 步（取值 → 判旧值 → `vus_unref` 旧值 → `vus_ref` 新值 → 回写）。
- 改动后：新增运行时函数 `vus_var_set(VusString **slot, void *newval)`，生成代码一行调用，ref/unref 在函数内一次完成。
- 收益：赋值路径代码量下降；循环内变量引用切换不再重复构造/转换。

### 2.3 列表/字典字面量 helper（`vus_object_list` / `vus_object_dict`）

- 改动前：`[a, b, c]` 被逐元素展开为冗长的"obj = vus_object_list(); vus_list_append(...); vus_ref(...)..."序列。
- 改动后：新增 `vus_object_list(void **items, int n)` / `vus_object_dict(...)`，字面量收敛为一次调用 + 参数数组。
- 收益：字面量密集代码（配置表、控件参数表）体积大幅缩小。

### 2.4 整数字面量池化

- 整数常量（含循环边界、下标）生成 `vus_literal("7")` 而非 `vus_string_new("7")`——走字符串常量池，多次同值共享一个实例。
- 收益：重复字面量不再各自 `malloc` + `memcpy`，生成代码与内存双降。

### 2.5 转文本转发（`vus_to_string` 直通）

- `转文本(入参)` 在入参已是字符串时直接转发引用，避免"先构造中间串再驻留"的冗余路径。

### 2.6 循环模板收敛（防缩进爆炸）

- 改动前：`for_range`/`for_each` 把循环体按行展开进 C 代码，循环嵌套时产生**按嵌套深度指数增长的缩进/块嵌套**。
- 改动后：循环模板收敛为单行紧凑块：
  - 循环值只构造一次（不再每次迭代重建）；
  - 块体合并为单行写入（避免缩进爆炸）。
- 收益：深层循环的 C 代码体积与 GCC 解析耗时显著下降。

### 2.7 `omit_main` 库式编译

- `VusConfig.omit_main` 为 1 时不生成 `main`（.vusx 插件、VUA/库式编译用），避免与宿主程序 `main` 多重定义冲突。

## 三、运行时优化（`rt/libvus_rt.c`）

### 3.1 字符串常量池 `vus_literal`

```c
VusString* vus_literal(const char* s);
```

- 以「哈希槽」缓存字面量字符串，命中（长度 + `memcmp`）直接返回共享实例。
- 应用：高频重复的键名/常量（如 `界面_设置("计数", v)` 的变量名、循环内重复整数文本）。
- 注意：常量池实例为共享引用，调用方仍应遵循既有 ref/unref 约定（池内持有引用）。

### 3.2 字符串拼接免二重复制 `vus_string_concat`

- 改动前：先算出总长 → 分配 → 两次 memcpy 拼接 → 中间多有临时缓冲。
- 改动后：直接分配目标 `VusString`（单块 malloc），一次性把两段数据写入 `data`，去掉中间缓冲与二次复制。

### 3.3 `VusString` 头 + 负载单块 malloc

- 结构体头（引用计数/长度/指针）与 `data` 负载一次 `malloc` 分配（头紧随负载），减少分配次数与缓存跳跃。

### 3.4 `vus_to_string` 整数值驻留缓存

- 高频小整数（如循环计数 `0..N`、下标）的文本结果缓存，热循环中避免反复 `snprintf`/`malloc`。
- 收益：`hot2.vus` 类循环里 `转文本(总和)`/`转数字("7")` 等高频路径占大头，命中缓存后耗时几乎归零。

### 3.5 变量赋值热路径 `vus_var_set`

- 与生成代码 2.2 配套：统一"新值 ref → 旧值 unref → 回写指针"，规避竞态与重复判断。

### 3.6 `vus_to_string` 长度优化

- 整数转文本按最坏位数精确分配，去除额外增长空间冗余。

## 四、编译器速度

- 体积下降直接降低 GCC 前端词法/语法/优化负担：大文件编译 **−29%**。
- 构建脚本对运行时采用预归档 + 差异策略：`libvus_rt.a` 一次编译，业务函数增量编译，避免"每轮全量重链运行时（含 yyjson/EasyLogger/GuiLite）"。

## 五、基准复现

```bash
# 1) 编译基准（big.vus 约 210KB）
time vus build --exe .bench/big.vus

# 2) 热循环运行基准（输出结果应为 "0" 或固定总和文本）
time vus run .bench/hot.vus    # 30 × 2000 次迭代
time vus run .bench/hot2.vus   # 50 × 50000 次迭代（10⁷ 级加法）

# 3) 生成代码体积
vus build --c-only .bench/big.vus
ls -la 构建/*.c
```

> 数值会随机器波动；对比时应使用同一台机器、同一组 `CFLAGS`（默认 `-O2`）与同一编译器版本，多次取中位数。
