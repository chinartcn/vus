# `.vus` 组件流脚本编写

> 组件流（VUA）里 `.vus` 是**逻辑脚本**：界面长什么样由 `.vua` 声明，**点下去干什么、数据从哪来、状态怎么变**由 `.vus` 决定。
> 本文专注 `.vus` 的写法：事件、状态、数据流、生命周期与调试。
> 前置：语言语法见 [TUTORIAL.md](../TUTORIAL.md)；界面/控件见 [01-VUA-组件流-从零到高级](01-VUA-组件流-从零到高级.md)。

---

## 1. 角色定位

| 文件 | 职责 | 谁来写 |
|------|------|--------|
| `xxx.vua` | 页面**骨架**：控件、布局、事件名、变量绑定声明 | 声明式，改文案/布局 |
| `yyy.vus` | 页面**血肉**：事件处理、状态读写、网络/JSON/文件 | 逻辑，改行为/数据 |
| `vua_controls.json` | 控件表（`type` 白名单 + 字段） | 加新控件类型时 |

示例工程里的对应关系（`testdata/`）：

```
vua_home.vua（按钮"打开逻辑"·事件名"打开逻辑"）
        │
        ▼ 界面_绑定("打开逻辑", 事件_打开逻辑)
vua_test.vus：定义 事件_打开逻辑(): 界面_显示("vua_logic.vua") + 绑定该屏事件
        │
        ▼ 用户在逻辑页点"加1"
vua_test.vus：定义 事件_加1(): 界面_设置("计数", 转文本(转数字(界面_取("计数")) + 1))
        │
        ▼ 渲染器做 View diff：只把"计数"文本从 0 → 1
```

**一句话**：`.vus` = 界面事件表 + 状态机 + 数据层；不关心 View 长什么样。

## 2. 启动与节目录

`.vus` 从上到下执行，**最后几行"起动"界面**（示例工程惯例）：

```vus
# ...一堆 定义 事件_XXX() ...

# ===== 启动段 =====
界面_显示("vua_home.vua")       # 切到主页（压栈）
界面_绑定("打开逻辑", 事件_打开逻辑)  # 把主页按钮事件接上函数
界面_绑定("打开设置", 事件_打开设置)
界面_绑定("打开课表", 事件_打开课表)
界面_绑定("加载课表", 事件_加载课表)
```

规则：
- **先 定义 全部事件函数，最后 界面_显示**（函数定义不进执行流，顺序无碍）。
- **每切一屏都要重新 界面_绑定 该屏事件**——事件表属于"当前屏"，
  换屏后旧屏的绑定不自动带过来。惯例是每个"打开 XXX"函数里连绑。

```vus
定义 事件_打开高级():
    界面_显示("vua_advanced.vua")
    界面_绑定("返回主页", 事件_返回主页)
    界面_绑定("选择记录", 事件_选择记录)
    界面_绑定("加载更多", 事件_加载更多)
```

## 3. 事件三要素（声明 → 注册 → 处理）

一个按钮从按下到执行，经过三个地方，名字必须一致：

```jsonc
// vua_advanced.vua —— ① 声明
{ "type": "列表", "id": "lst", "事件": { "事件名": "选择记录" } }
```

```vus
// vua_test.vus —— ② 注册（导航进屏时）
界面_绑定("选择记录", 事件_选择记录)

// —— ③ 处理（函数按名接住）
定义 事件_选择记录(下标, 值):
    界面_设置("选中记录", "第 " + 下标 + " 行：" + 值)
```

### 3.1 参数怎么来

事件触发时 Java 侧打包一个**变量 JSON**，其**键名就是函数参数名**：

| 触发来源 | 自动带的参数 |
|----------|--------------|
| 列表行点击 | `下标`（int，字符串形态）+ `值`（行标题），再并入 `事件.收集变量` 的输入值 |
| 普通按钮 | `事件.回调变量`（`"星级=3"` → `星级`=`"3"`） + `事件.收集变量`（输入控件变量） |
| 网页 JS `window.vus.onEvent("保存", "{\"正文\":\"...\"}")` | **JSON 里的键**，如 `正文` |
| 滚动到底"加载更多" | 空 `{}`（无参数） |

```vus
定义 事件_调整星级(变量, 值):
    界面_设置(变量, 值)
    # 网页回调示例：界面_绑定("保存", 事件_保存)
定义 事件_保存(正文):
    打印(正文)
```

> 参数个数只需覆盖**你要用的**键：JSON 里多余的键忽略，缺的键参数取空串。

## 4. 状态读写（界面_设置 / 界面_取）

**变量是 `.vua` 与 `.vus` 之间的唯一状态通道。**

- 声明：控件带 `variable` 键。
- 写：`界面_设置("变量名", 值)` —— 渲染器找绑定该变量的输入框/文本 **只更新那一处**（View diff）。
- 读：`界面_取("变量名")` —— 输入框取**当前输入内容**，文本取**当前显示**。

```vus
定义 事件_加1():
    界面_设置("计数", 转文本(转数字(界面_取("计数")) + 1))

定义 事件_清零():
    界面_设置("计数", "0")
    界面_设置("奇偶", "?")
```

对应 `vua_logic.vua`：

```json
{ "type": "文本", "variable": "计数", "内容": "0", "样式": "headline" },
{ "type": "输入框", "id": "in_note", "variable": "备注", "标签": "备注", "提示": "输入任意文本" }
```

读写类型注意：`界面_取` 总是字符串，做算术先 `转数字`，回写再 `转文本`。

## 5. 数据流：网络 + JSON → 状态 → 界面

经典三段（示例工程"课表"页就是这个模式）：

```vus
定义 事件_加载课表():
    数据 = 网络_GET("https://gitee.com/rtccn_mc/vus/raw/master/apk_class.json")
    如果 数据 == "":                      # 失败/空响应统一判空
        打印("课表下载失败")
        返回
    结束
    标题 = 对象文本(JSON_查询(数据, "标题"))
    星期串 = JSON_生成(JSON_查询(数据, "星期"))     # 数组 → JSON 文本
    节次串 = JSON_生成(JSON_查询(数据, "节次"))
    课程串 = JSON_生成(JSON_查询(数据, "课程"))
    树 = "{\"type\":\"界面\",\"标题\":\"" + 标题 +
         "\",\"子组件\":[{\"type\":\"课表\",...}]}"
    界面_显示_JSON(树)                    # 动态上屏
```

要点：
- `网络_GET/网络_请求` 返回**响应体原文**（APK 侧包装已被运行时解包），失败返回空串。
- `JSON_查询(文本, "键")` 取字段；`对象文本(...)` 转字符串；`JSON_生成(...)` 序列化数组/对象。
- 静态数据用 `.vua` 写死；**动态数据用 `界面_显示_JSON` 拼树**（列表分页、课表、详情页都这么干）。

## 6. 列表的数据流（加载更多/分页）

列表的"数据"目前是 `.vua` 里的静态数组；**真实数据用 `界面_显示_JSON` 重建列表节点**，配合"加载更多"事件实现分页。跨事件共享的中间状态（如页码）用一个 `variable` 文本节点承载（见第 4 节的状态通道）：

```vus
定义 事件_加载更多():                 # 滚动到底触发（渲染器监听，不会连环触发）
    页码 = 转数字(界面_取("数量")) + 1
    界面_设置("数量", 转文本(页码))
    # 1) 拉下一页
    批次 = 网络_请求("GET",
                  "https://api.example.com/posts?page=" + 转文本(页码),
                  "{\"Authorization\":\"Bearer " + token + "\"}", "", 15, 2)
    # 2) 拼出新列表节点（标题来自服务端）
    列表串 = JSON_生成(JSON_查询(批次, "列表"))
    树 = "{\"type\":\"界面\",\"标题\":\"帖子\",\"子组件\":[" +
         "{\"type\":\"列表\",\"id\":\"lst\"," +
         "\"事件\":{\"事件名\":\"选择记录\"}," +
         "\"加载更多\":\"加载更多\"," +
         "\"数据\":" + 列表串 + "}]}"
    界面_显示_JSON(树)                 # 重建后滚动/点击事件仍有效（事件名没变）
```

> 事件名不变（`选择记录`/`加载更多`），重建后绑定依然生效——事件表按名注册，与控件实例无关。

## 7. 网页 JS → VUS 的回传

`.vus` 侧和平常一样绑定即可，JS 侧调桥：

```vus
界面_显示("vua_web.vua")          # 页面里有 { "type": "网页", ... }
界面_绑定("保存", 事件_保存)
界面_绑定("返回主页", 事件_返回主页)

定义 事件_保存(正文):
    文件_写入("posts/" + 日期_时间戳() + ".txt", 正文)
    界面_设置("状态", "已保存")
```

```js
// 网页内的 JS
document.querySelector("#btn").onclick = function () {
  window.vus.onEvent("保存", JSON.stringify({正文: "来自网页的文本"}));
};
```

回传链路自动切主线程，不用担心跨线程问题。

## 8. 换屏生命周期（记忆清单）

| 时机 | 你要做的 |
|------|----------|
| 进入某屏 | `界面_显示(...)` 后立即绑定该屏全部事件 |
| 需要初始化数据 | 绑定后立即 `界面_设置`/`网络_*` 回填（如"下载并显示课表"） |
| 用户操作 | 事件函数里读写状态/重绑/换屏 |
| 返回 | `界面_返回()`/`界面_返回至(名)`；回主页时主页 View 走缓存，无需重绑 |
| 页面缓存注意 | 输入框内容随 View 保留；**代码里 `界面_设置` 的中间状态在页面缓存命中时保留旧快照**，有"秘而不宣"的值要进 `.vua` 的 `内容`/在进入函数里明确重置 |

## 9. 调试三板斧

1. **桌面验语法**（秒级，无真机）：

   ```bash
   cd vus && ./vus build --c-only testdata/vua_test.vus
   ```

   语法/类型错误、`界面_绑定` 拼写的函数名漏定义（generator 会报未定义）都在这里查出。

2. **打印"埋点"**：`打印("加1 事件，当前=" + 界面_取("计数"))` —— APK 侧走 elog，
   在 logcat 里观察（`adb logcat | grep VUS` 或日志过滤后跟 `打印` 内容）。

3. **纯逻辑先行**：把网络/JSON/算法放进独立函数（不带 `界面_*`），先写个 `test_普通脚本.vus`
   在桌面 `./vus run` 跑通数据层，再接界面。界面本身只能 APK 验证
   （`tests/vua_smoke` 是 native 渲染树单测，不测 Java View）。

## 10. 模式与反模式

✅ **推荐**

```vus
# 一个事件一个函数，职责单一
定义 事件_登录():
    # 网络 → 状态 → 反馈
定义 事件_选择记录(下标, 值):
    # 界面_设置 + 可选界面_显示_JSON 详情
```

❌ **别这么写**

| 反模式 | 为什么 |
|--------|--------|
| 事件函数里循环 `网络_GET` 大量请求 | 阻塞串行拉取（APK 桥虽切线程但仍是同步等待）→ 一次只拉必要数据 |
| `界面_绑定` 写在文件顶部 | 绑定是"当前屏"协议；乱绑会收到别的屏失效事件名 |
| 用 `界面_取` 传大 JSON | 它是变量通道，不是数据总线；结构化数据走 `JSON_查询`/字典 |
| 直接操作 `对话框/Toast` 类控件 | 目前无此控件；反馈字段用`variable` 文本 + `界面_设置` |

## 11. 完整示例：带分页的帖子列表

页面（`vua_posts.vua`）：

```json
{
  "type": "界面", "标题": "帖子",
  "子组件": [
    { "type": "列表", "id": "lst",
      "事件": { "事件名": "选择记录" },
      "加载更多": "加载更多",
      "高度": 500,
      "数据": [ { "标题": "加载中...", "副标题": "往下滑加载更多" } ] },
    { "type": "文本", "variable": "数量", "内容": "0" },
    { "type": "文本", "variable": "状态", "内容": " " },
    { "type": "按钮", "文字": "返回", "事件": { "事件名": "返回主页" } }
  ]
}
```

脚本（`vua_posts_seg.vus` 片段）：

```vus
定义 事件_打开帖子():
    界面_显示("vua_posts.vua")
    界面_绑定("返回主页", 事件_返回主页)
    界面_绑定("选择记录", 事件_选择记录)
    界面_绑定("加载更多", 事件_加载更多)
    界面_设置("状态", "进入：加载第 1 页")

定义 事件_选择记录(下标, 值):
    界面_设置("状态", "打开：" + 值)
    # 详情可再 界面_显示_JSON 拼一张详情页

定义 事件_加载更多():
    页码 = 转数字(界面_取("数量")) + 1     # "数量" 是 vua_posts.vua 里的 variable 文本节点
    界面_设置("数量", 转文本(页码))
    批次 = 网络_请求("GET",
                  "https://api.example.com/posts?page=" + 转文本(页码),
                  "", "", 15, 2)
    如果 批次 == "":
        界面_设置("状态", "第 " + 转文本(页码) + " 页加载失败")
        返回
    结束
    列表串 = JSON_生成(JSON_查询(批次, "标题"))
    树 = "{\"type\":\"界面\",\"标题\":\"帖子\",\"子组件\":[" +
         "{\"type\":\"列表\",\"事件\":{\"事件名\":\"选择记录\"}," +
         "\"加载更多\":\"加载更多\",\"数据\":" + 列表串 + "}]}"
    界面_显示_JSON(树)
    界面_设置("状态", "已加载到第 " + 转文本(页码) + " 页")
```

把以上保存为 `testdata/vua_posts.vua` + 在 `vua_test.vus` 加 `事件_打开帖子` 并在首页绑定，
重建 APK（[03-APK-构建与发布](03-APK-构建与发布.md)）即可真机体验"滑到底自动分页"。
