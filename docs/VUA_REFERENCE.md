# VUA 界面定义规范（Android 组件流）

> **当前状态：已实现（v3.0.20260904150204（正式版））**
> 本文档定义 VUS 在 **Android 机制**下的界面组件定义语言 `.vua`。它描述"界面长什么样"，不含任何逻辑；逻辑统一放 `.vus`（VUS 语言）。
> 实现依据：native `rt/vua.c/h`（解析/校验/渲染树/事件派发）+ APK 壳 `examples/vua-android`（`VuaRenderer.java` 建 View）+ `.vus` 侧 `界面_*` 内置函数（`src/generator.c` 映射）。冒烟测试：`tests/vua_smoke.c`。

## 一、定位：两套独立 UI 机制

VUS 现有两套互不借用、边界清晰的 UI 机制，**不要混谈**：

| 机制 | 平台 | 界面形态 | 文件 |
|------|------|----------|------|
| **画布交互流** | Termux / Linux X11 | `图形_*` 绘制（GuiLite）+ 事件轮询/回调 | 单文件 `.vus` |
| **组件解析流**（本文） | Android APK | `.vua` 定义组件 + `.vus` 逻辑 + APK 原生 View 渲染 | `.vua` + `.vus` |

两者各自闭环。`.vua` **只属于 Android 组件解析流**；X11/Termux 画布流没有 `.vua`。后缀即规则：想被 Android 渲染，就走 `.vua`。

## 二、运行机制（已实现）

```
.vus 逻辑（VUS 语言）—— .vua 界面定义（中文 JSON）
      │  界面_显示(路径) / 界面_显示_JSON(串) / 界面_返回() / 界面_返回至(名)
      │  界面_绑定(事件名, 函数) / 界面_设置(变量, 值) / 界面_取(变量)
      ▼
 rt/vua.c  VuaSession（屏栈）
      │  vua_screen_load：yyjson 解析 → 严格校验（type 在控件表、属性在词典）→ 建组件树
      ▼
 规范化渲染树（vua_screen_dump_rendertree，JSON + 64 位指纹）
      │  └─ 格式见《VUA_RENDER_TREE.md》
      ▼
 APK Java 侧 VuaRenderer.java → Android 原生 View 组树（LRU 页面缓存）
      │
 用户触摸 → Java 取节点 event（name / triggerId）→ 收集变量字典
      │
      ▼
 vua_trigger_event / vua_trigger_by_id（native，按名查事件表 → 调 .vus 绑定的函数闭包）
```

- 屏栈变化（`界面_显示`/`界面_返回`/`界面_返回至`/`界面_显示_JSON`）触发重绘钩子（native → Java 重建 View）。
- 事件表由 `.vus` 的 `界面_绑定` 登记：`.vua` 只写"事件名"，运行时按名解析到已在事件表上登记的处理函数。
- 换界面**只改 `.vua`**（或运行时用 `界面_显示_JSON` 动态上屏），不重打包 APK。
- **native 把 `.vua` 解析/校验/翻译后再以规范化渲染树交给 Java 去建 Android View**；渲染树 JSON 格式见 [VUA_RENDER_TREE.md](VUA_RENDER_TREE.md)。

## 三、基础结构

一个 `.vua` 文件必须是单个 JSON 对象，根节点为一个 `界面`：

```json
{
  "type": "界面",
  "标题": "主界面",
  "主题": "light",
  "子组件": [
    { "type": "文本", "内容": "你好，世界" }
  ]
}
```

- 根节点 `type` 必须是 `界面`，它是唯一合法的顶层容器。
- 其余容器/控件都放在 `子组件`（children）数组里。
- **所有 `type` 与属性名都用中文**（见第五节的权威 type 表与"字段词典"）。

## 四、数据结构

### 组件的通用形态

每个控件通常是单个 JSON 对象，不同控件共用同一套骨架：

| 字段 | 说明 | 必备 |
|------|------|:----:|
| `type` | 控件类型名（中文），经第七节控件表定位实现 | ✅ |
| `id` | 控件唯一标识，用于同屏内区分同名控件 | 视控件 |
| 属性… | 控件具体属性（经第九节字段词典翻译为控件内部字段） | —— |
| `变量` | （输入控件）把当前值写入的具名变量 | 可选 |
| 事件属性 | （交互控件）如 `点击`：事件名 + 回调变量 | 可选 |

### 表单变量收集规则

`.vua` 的"表单状态"统一收敛成一张 **`变量 → 值` 的字典**，靠 `变量` 与 `回调变量` 两个属性建立读写关系：

1. **变量即表单状态**：整个 `.vua` 维护一张 `{ 变量名 : 值 }` 表。用户输入、事件回调都围绕这张表进行。
2. **写入来源**：凡带 `变量` 属性的输入控件，用户在界面编辑时，把它当前值写入该变量名。
3. **读取来源**：事件控件声明的 `回调变量` 列表，指明触发时从哪些变量取值；取出的值作为一个"变量名 → 值"字典传给 `.vus` 逻辑。
4. **作用域**：`变量` 默认在整屏（`界面`）生命周期内有效，跨控件、跨事件可见。
5. **多写一**：同一变量名被多个输入控件写入时，**以最近一次用户输入为准**（后写覆盖先写）。
6. **取值时机**：事件触发时读的是"该变量当时的最新值"，不受声明顺序影响。
7. **默认类型**：变量值按**字符串**处理；后续如需数值/布尔，可通过词典或转换约定扩展。
8. **写入时机**（关键）：变量**只在控件"值确认"时写入**——对输入框即"失焦/提交"时，避免把半截输入写进状态。如需实时（每键都写），给该输入控件加 `实时: true`。事件统一用「变化」（值确认）与写入取同一时机，**不要混用**逐键 `onInput` 与"变化"两套时刻，否则状态会在"输一半"时被污染。

示例（一个表单 + 一个读它的按钮）：

```json
{
  "type": "界面",
  "标题": "记账",
  "子组件": [
    {
      "type": "表单",
      "输入": [
        { "type": "输入框", "标签": "金额", "变量": "金额" },
        { "type": "输入框", "标签": "备注", "变量": "备注" }
      ]
    },
    {
      "type": "按钮",
      "文字": "保存",
      "点击": {
        "事件名": "保存账单",
        "回调变量": ["金额", "备注"]
      }
    }
  ]
}
```

↑ 用户输入 `金额`/`备注` 后点"保存" → 事件 `保存账单` 收到字典 `{金额:…, 备注:…}`。

## 五、内置控件类型

以下为本规范的内置控件。**`type` 只用中文**；控件表（第七节）把这些中文 `type` 映射到对应控件实现（`.so`）。

### 1) 容器 / 布局（负责排列，职责通用，稳定）

| `type`（中文） | 作用 | 主要属性 |
|--------|------|----------|
| `界面` | 一屏的根容器 | `标题`，`子组件`，`主题` |
| `列` | 纵向堆叠 | `子组件`，`间距` |
| `行` | 横向排布 | `子组件`，`间距` |
| `卡片` | 卡片容器 | `子组件` |
| `表单` | 聚合一组输入控件 | `输入`（数组，每项为输入控件） |
| `分隔线` | 分隔线 | —— |
| `占位` | 占位 | `高度` / `宽度` |

### 2) 交互控件（有输入 / 有点击）

| `type`（中文） | 作用 | 事件属性 |
|--------|------|----------|
| `按钮` | 按钮 | `点击` |
| `输入框` | 单行输入 | `变化` |
| `多行输入` | 多行输入 | `变化` |
| `复选框` | 复选 | `变化` |
| `开关` | 开关 | `变化` |
| `单选组` | 单选组 | `变化` |
| `下拉` | 下拉选择 | `变化` |
| `标签组` | 标签组（单/多/展示） | `变化` |
| `滑块` | 滑块 | `变化` |

> 输入控件的「变化」仅指**值确认**（失焦/提交）时的事件；变量的实际写入时机见第四节规则 8。

> **实现状态**：当前 APK 内置控件表（`testdata/vua_controls.json`）已登记 `界面/列/行/卡片/文本/按钮/输入框/复选框/开关/滑块/下拉/图标/图片/列表/网页/课表/侧边栏`；`VuaRenderer.java` 使用 Android SDK 标准 View（`TextView/Button/EditText/CheckBox/Switch/SeekBar/Spinner/ImageView/LinearLayout/TableLayout/ListView/WebView/FrameLayout` 等）逐 `type` 建控件；其中 `列表` 用 ListView + Adapter（`convertView` 复用，只渲染可视区，长列表不卡；数据项对象带非空 `节标题` 字段渲染为分组头行，如 `分组列表` 布局模板所用），`网页` 用 WebView（`url`/`html`/`内容`(Markdown) 三种输入，JS 经 `window.vus.onEvent` 回接 `vuaTrigger`），`侧边栏` 用 FrameLayout 手写 Drawer 容器（无第三方依赖：菜单面板 + 主内容 + 遮罩，边缘 20dp 拖出/遮罩点击收起，菜单项点击载荷与 `列表` 一致 `{"下标","值"}`）。控件表之外的 `type` 按"扩展控件"处理——需要先在控件表登记、并由 Java 侧或 `.vaz` 展开提供实现。
>
> **资源加载**：`MainActivity.extractAssets` 把 assets 里**全部文件**（不限扩展名：`.vua/.json/.png/.jpg/.webp/.svg/.gif/.ttf/.otf/.zip` 等）释放到应用 `filesDir`，作为本地资源根。`文件_上传`/`文件_读取` 与控件引用资源的相对路径均相对该目录解析。**图标包 = 一组命名 png + 名称索引**：`图标` 控件（见下）按 `名称` 查找 `filesDir` 下的位图文件，缺图时渲染占位文本兜底。**图片格式边界**：位图解码走 Android `BitmapFactory`，支持 png/jpg/webp（含动图首帧）与 gif **静态首帧**；**svg 未接入**（桌面 `rt/nanosvg` 有、APK 暂无），矢量/动图方案不在当前范围。

### 3) 展示控件

| `type`（中文） | 作用 |
|--------|------|
| `文本` | 文本（`内容` / `样式`；**`字体`**(或 `font`) 可指定 filesDir 下 `.ttf/.otf` 相对路径，加载失败静默回退系统字体） |
| `图片` | 图片 |
| `图标` | 图标（`名称`/`src` 指向 filesDir 下的 png/jpg/webp 位图，`宽`/`高` 控制尺寸，`标签` 做无障碍描述；缺图渲染占位文本） |
| `指标` | 大号数值/指标 |
| `角标` | 角标/状态 |
| `列表` | 列表 |
| `侧边栏` | 抽屉（滑出/收起） |
| `表格` | 表格 |

### type 别名（兼容旧写法）

历史/英文写法作为"别名"接受，运行时经词典归一到上面的中文 `type`：

```
screen→界面  column→列  row→行  card→卡片  text→文本  image→图片  icon→图标
button→按钮  text_input→输入框  tarea→多行输入  checkbox→复选框  switch→开关
select→下拉  slider→滑块  list→列表  web→网页  table→表格  drawer/sidebar→侧边栏  ...
```

**新写的 `.vua` 一律用中文 `type`**；别名仅为保证旧文件可读，不建议再用（否则词典联想易打架）。

> 控件表里没有的内置控件，同样按"扩展控件"处理（见第十二节）——本规范不强制穷尽列表。

## 六、事件绑定

`.vua` 不写逻辑。事件**事件名**与**取值来源**都由 `.vua` 声明，运行时按名回调到 `.vus`：

1. **输入控件带 `变量`**：每个输入控件声明把当前值写入一个具名"变量"。表单状态即收集在这组变量里。
2. **事件声明 `事件名` + `回调变量`**：触发时把指定变量的值一并交给逻辑。

```json
{
  "type": "界面",
  "标题": "记账",
  "子组件": [
    {
      "type": "表单",
      "输入": [
        { "type": "输入框", "标签": "金额", "变量": "金额" },
        { "type": "输入框", "标签": "备注", "变量": "备注" }
      ]
    },
    {
      "type": "按钮",
      "文字": "保存",
      "点击": {
        "事件名": "保存账单",
        "回调变量": ["金额", "备注"]
      }
    }
  ]
}
```

按下 `保存` → 查 `.vus` 里的 `保存账单` 函数，并把当前变量 `金额`、`备注` 的值一并传入。

### 取值来源

- `变量`（输入控件）：声明"我写到哪个变量"。一个输入控件只写一个变量，值是它的当前输入。
- `回调变量`（事件控件）：声明"触发时把哪些变量的值带给逻辑"。可为空（纯事件通知）。

### 事件分发（已实现）

```
用户点击 → Android View 触发
   → Java 取该节点渲染树里的 event（name 或 triggerId → 树顶层 eventIndex 查询）
   → JNI 回 native：vua_trigger_event(name, 变量字典) 或 vua_trigger_by_id(id)
       → 查"事件名 → 逻辑函数"登记表（.vus 侧用 界面_绑定 登记，VusClosure）
           → 命中：调用，传入变量值字典
           → 未命中：报错（不静默）
```

- `.vua` 渲染层（Java）只负责"点击 → 取事件名 → 回传 native"，不接触 `.vus` 内部。
- "事件名 → 函数"登记表由 `.vus` 逻辑侧 `界面_绑定(事件名, 处理函数)` 提供；事件处理函数带可选参数（由组件回填 `变量`）。

## 七、JSON 控件表（中文 type → 实现/校验）

控件表是一份 JSON，负责登记 `.vua` 里的**中文 type** 及其**可接受字段**，是"可拓展"的登记处，也是 `vua_screen_load` 严格校验的依据：

```json
{
  "控件表": {
    "按钮":   { "so": "libvua_基本.so" },
    "文本":   { "so": "libvua_基本.so" },
    "输入框": { "so": "libvua_基本.so" },
    "迷你图": { "so": "libvua_图表.so", "字段": { "数据": "value", "颜色": "color" } }
  }
}
```

实际落地文件见 `testdata/vua_controls.json`（当前用 `字段` 声明每个控件接受的属性名，未用 `so` 键）：

```json
{ "控件表": {
    "界面": { "字段": { "标题": {}, "子组件": {} } },
    "文本": { "字段": { "内容": {}, "样式": {} } },
    "按钮": { "字段": { "文字": {}, "样式": {} } },
    "输入框": { "字段": { "标签": {}, "提示": {} } },
    "滑块": { "字段": { "值": {}, "标签": {}, "最小值": {}, "最大值": {} } }
} }
```

- **控件表的键是权威中文 `type`**；英文别名（如 `button`）只在第五节的别名层被归一，不建议直接作为键。
- `so` 字段：设计用于指向承载控件实现的依赖，APK 能读到即可（见第八节——当前实现控件即 APK 内 Java View，无需 .so）。
- `字段`（可选）：控件自带字段词典，覆盖全局词典；同时用于加载期校验"未知字段报错"（见第十节）。

### 解析流程（已实现）

```
遇到中文 type
   → vua_screen_load 读控件表/词典
       → type 不在控件表（未知字段）→ 直接报错（VUA_ERR_UNKNOWN_TYPE / VUA_ERR_UNKNOWN_FIELD）
       → 命中 → 归一化渲染树 → Java 按 type 建 View（未注册 type 则报错，不静默）
```

## 八、控件依赖（设计说明）

> 原草案按".so 即插即用控件"设计；**当前实现里控件即 APK 内 Java View（编译进 dex）**，通过 `type` 在 `VuaRenderer.java` 分发，不涉及 `.so` 加载。本节保留为未来"真正 .so 控件库"的设计约定，不作为当前实现约束。

只要满足以下两条，该控件依赖就能在 `.vua` 里被登记使用：

1. Android APK **能读到/能加载**它（`System.load` 或资源可访问，当前为 dex 内 View 类）。
2. 在控件表里登记了一个中文 `type` 名。

控件内部是 JNI 方法、native 导出函数还是其他形式，**由控件自己决定**，本规范不设统一 ABI 门槛——避免给扩展设限。

### 最小示例：如何把一个真实控件接进 `.vua`（当前做法）

以"按钮"为例（`VuaRenderer.java` 的实际做法）：

1. **写控件**：`VuaRenderer` 里按 `type` 分支创建 Android 标准 View（如 `Button`），读取渲染树节点属性（如 `文字`）设置显示，`id` 关联触发。
2. **打进 APK**：Java 源码随 APK 打包；亦可扩展 `ExtensionLoader` 动态加载 `.dex` 插件（见 `examples/vua-android/plugins/sample`）。
3. **登记控件表**：`vua_controls.json` 里登记一行 `中文type → 字段表`。
4. **`.vua` 里直接用**：
   ```json
   { "type": "按钮", "文字": "保存", "点击": "保存进度" }
   ```

> 这条路径说明"扩展一个真实控件"有据可循：控件 = 一个"能被 APK 读到、能按 type 取到、属性/事件经词典对齐"的 View 实现。当前已走通「控件表 → 词典 → .vua → 触发事件」链路，其余控件照此复制。

## 九、字段词典（中文 ↔ 控件内部字段）

`.vua` 写中文属性名，控件内部可能有自己的字段名。二者靠**词典**翻译，查找顺序：

```
1. 控件自带字段词典（.vua 控件表里 `字段` 字段）→ 最优先
2. 全局词典文件（如 vua_dict.json，一份可编辑文件）→ 默认兜底
3. 都没有 → 报"未知字段"错误
```

- **全局词典只是一份文件**，不是写死在代码里。要改词、加词，直接编辑该文件即可，零代码改动。
- 扩展控件想自定义中文名，在自己的 `字段` 里加词典即可覆盖默认。

示例（全局词典文件 `vua_dict.json`）：

```json
{
  "词典": {
    "文字": "label",
    "内容": "value",
    "样式": "style",
    "提示": "placeholder",
    "子组件": "children",
    "点击": "onClick",
    "变化": "onChange"
  }
}
```

## 十、错误处理

**原则：直接报错，不静默降级。** 避免用户看到"界面没反应却不知道为什么"。

| 情形 | 行为 |
|------|------|
| `.vua` 里出现控件表中没有的 `type` | 加载期报错 `VUA_ERR_UNKNOWN_TYPE`（"未知类型"）|
| `.vua` 属性不在字段词典 | 加载期报错 `VUA_ERR_UNKNOWN_FIELD`（"未知字段"）|
| `.vua` JSON 语法错误 | 报错 `VUA_ERR_JSON`，native `vua_screen_load` 失败并挂错误链 |
| 根节点 type 不是 `界面` | 报错 `VUA_ERR_ROOT` |
| 事件名绑定不到处理函数 | 触发时报 `VUA_ERR_BINDING`（不静默）|

## 十一、离线校验（vus lint）

错误不应等装机后才发现。`vus lint` 提供独立的 `.vua` 离线校验命令：读控件表（`--controls` / `VUS_VUA_CONTROLS` / 缺省探测 `vua_controls.json`、`testdata/vua_controls.json`）→ 对每个 `.vua` 走与装载期完全相同的严格校验（复用 `rt/vua.c` 的 `vua_screen_load` + `vua_screen_dump_rendertree`，与 `tests/vua_smoke.c` 同套逻辑）→ 输出渲染树指纹。

```bash
vus lint vua_home.vua vua_settings.vua          # 默认探测控件表
vus lint --controls vua_controls.json *.vua     # 显式指定控件表
```

| 检查项 | 说明 | 状态 |
|--------|------|:----:|
| `type` 在控件表 | 每个 `type` 必须是控件表中的中文 `type`（可归一的别名按第五节处理） | ✅ 加载期校验 |
| 字段在词典 | 每个属性名都要能经词典翻译成控件内部字段（控件自带词典 > 全局词典） | ✅ 加载期校验 |
| 事件名绑上函数 | 每个事件属性里的 `事件名` 都能在 `.vus` 里找到对应的逻辑函数 | ⚠️ 运行时触发时报错（`界面_绑定` 后才可查）|
| JSON 语法 | `.vua` 是合法 JSON | ✅ 加载期校验 |
| 引用控件存在 | 控件依赖在 APK 打包清单里存在 | ⚠️ 打包期人工核对 |

> `vus lint` 已实现（`src/vua_lint.c`），并补上 LSP 校验闭环：编辑器打开/编辑/保存 `.vua` 时发布 `textDocument/publishDiagnostics`（source=`vua-lint`），IDE 内即时暴露校验错误。冒烟覆盖：`tests/lint_smoke.sh`（CLI）与 `tests/lsp_smoke.sh`（LSP 诊断）。

## 十二、可拓展流程

**加一个新控件（当前做法）：**
1. 在 `VuaRenderer.java`（或 dex 插件）里实现该 `type` 的 View 构建与事件回传。
2. 在 JSON 控件表（`vua_controls.json`）里登记一行：`中文type → 字段表`。
3. 重新打包 APK 一次（控件入库）。
4. 之后 `.vua` 里即可用它，后续换界面**不再重打包**（也可用 `界面_显示_JSON` 完全运行时动态上屏）。

**加一个字段 / 改字段名：**
- 编辑控件表里该控件的 `字段`（或全局词典文件）——不碰解析器、不碰代码。

## 十三·五、语言侧内置函数（界面_*，`.vus` 驱动）

`.vua` 是纯数据，全部驱动都发生在 `.vus`（经 `src/generator.c` 映射到 `rt/vua.c`）：

| `.vus` 调用 | 运行时 | 说明 |
|------------|--------|------|
| `界面_显示(路径)` | `vua_session_show` | 读 `.vua` 文件解析并压栈成为当前屏；成功后触发重绘 |
| `界面_显示_JSON(串)` | `vua_show_json` | 把 `.vua` 格式 JSON **字符串**直接上屏（动态渲染树，数据组装界面）|
| `界面_返回()` | `vua_session_back` | 弹栈回上一屏（已在底屏则不弹）|
| `界面_返回至(名)` | `vua_session_back_to` | 弹到指定屏名的那一屏 |
| `界面_绑定(事件名, 函数)` | `vua_on` | 把 `.vus` 函数登记为事件名 handler（编译期包成 `VusClosure`）|
| `界面_设置(变量, 值)` | `vua_state_set` | 写入当前屏变量状态；带 `变量` 的文本控件会回填显示 |
| `界面_取(变量)` | `vua_state_get_or_empty` | 读取当前屏变量状态（缺失返回空串）|

一套标准生命周期：

```python
界面_显示("主界面.vua")
界面_绑定("打开设置", 页_打开设置)

定义 页_打开设置():
    界面_显示("设置.vua")
    界面_绑定("返回主页", 页_返回主页)

定义 页_返回主页():
    界面_返回()
```

> 说明：API 层还有 `界面_触发`（`vua_trigger_event`）等由 Java 触摸回传调用的入口；`界面_绑定` 为"同名覆盖"——重复登记同名事件以最近一次为准。
