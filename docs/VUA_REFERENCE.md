# VUA 界面定义规范（Android 组件流）

> **当前状态：草案 v0.1**（待实现）
> 本文档定义 VUS 在 **Android 机制**下的界面组件定义语言 `.vua`。它描述"界面长什么样"，不含任何逻辑；逻辑统一放 `.vus`（VUS 语言）。

## 一、定位：两套独立 UI 机制

VUS 现有两套互不借用、边界清晰的 UI 机制，**不要混谈**：

| 机制 | 平台 | 界面形态 | 文件 |
|------|------|----------|------|
| **画布交互流** | Termux X11 | `图形_*` 绘制 + 你自己的回调机制处理点击 | 单文件 `.vus` |
| **组件解析流**（本文） | Android | `.vua` 定义组件 + `.vus` 逻辑 + APK 原生 View 渲染 | `.vua` + `.vus` |

两者各自闭环。`.vua` **只属于 Android 组件解析流**；X11 画布流没有 `.vua`。后缀即规则：想被 Android 渲染，就走 `.vua`。

## 二、运行机制

```
vus_start.json（程序清单/入口）
      │  定义初始入口
      ▼
 启动 .vus（逻辑侧，VUS 语言编写）
      │
  加载/渲染 .vua（组件定义，中文 JSON）
      │
      ▼
 .vua 解析器（借鉴 kai-ui，见"附录：借鉴说明"）
      │  按中文 type 查 JSON 控件表 → 定位到控件(/.so)
      ▼
 字段词典（.so 自带词典 > 全局词典文件 > 报错）
      ▼
 规范化渲染树（native 产出，Java 消费）
      │  └─ 格式见《VUA_RENDER_TREE.md》
      ▼
 APK 原生 View 渲染组件树
      │
 事件按名回调（.vua 里的事件名 → 调 .vus 里同名函数）
```

**核心原则**：
- `.vua` 是数据（界面声明），不是代码。
- 事件只写"名字"，运行时按名字解析到 `.vus` 的函数。
- 控件库打进 APK 是**固定的一次打包**；换界面**只改 `.vua`**，不重打包、不重编控件。
- **native 把 `.vua` 解析/校验/翻译后再以规范化渲染树交给 Java 去建 Android View**；渲染树 JSON 格式见 [VUA_RENDER_TREE.md](VUA_RENDER_TREE.md)。

## 三、基础结构

一个 `.vua` 文件必须是单个 JSON 对象，根节点为一个 `界面`：

```json
{
  "type": "界面",
  "标题": "主界面",
  "主题": "light",
  "子组件": [
    { "type": "文本", "内容": "你好，世界" }
  ]
}
```

- 根节点 `type` 必须是 `界面`，它是唯一合法的顶层容器。
- 其余容器/控件都放在 `子组件`（children）数组里。
- **所有 `type` 与属性名都用中文**（见第五节的权威 type 表与"字段词典"）。

## 四、数据结构

### 组件的通用形态

每个控件通常是单个 JSON 对象，不同控件共用同一套骨架：

| 字段 | 说明 | 必备 |
|------|------|:----:|
| `type` | 控件类型名（中文），经第七节控件表定位实现 | ✅ |
| `id` | 控件唯一标识，用于同屏内区分同名控件 | 视控件 |
| 属性… | 控件具体属性（经第九节字段词典翻译为控件内部字段） | —— |
| `变量` | （输入控件）把当前值写入的具名变量 | 可选 |
| 事件属性 | （交互控件）如 `点击`：事件名 + 回调变量 | 可选 |

### 表单变量收集规则

`.vua` 的"表单状态"统一收敛成一张 **`变量 → 值` 的字典**，靠 `变量` 与 `回调变量` 两个属性建立读写关系：

1. **变量即表单状态**：整个 `.vua` 维护一张 `{ 变量名 : 值 }` 表。用户输入、事件回调都围绕这张表进行。
2. **写入来源**：凡带 `变量` 属性的输入控件，用户在界面编辑时，把它当前值写入该变量名。
3. **读取来源**：事件控件声明的 `回调变量` 列表，指明触发时从哪些变量取值；取出的值作为一个"变量名 → 值"字典传给 `.vus` 逻辑。
4. **作用域**：`变量` 默认在整屏（`界面`）生命周期内有效，跨控件、跨事件可见。
5. **多写一**：同一变量名被多个输入控件写入时，**以最近一次用户输入为准**（后写覆盖先写）。
6. **取值时机**：事件触发时读的是"该变量当时的最新值"，不受声明顺序影响。
7. **默认类型**：变量值按**字符串**处理；后续如需数值/布尔，可通过词典或转换约定扩展。
8. **写入时机**（关键）：变量**只在控件"值确认"时写入**——对输入框即"失焦/提交"时，避免把半截输入写进状态。如需实时（每键都写），给该输入控件加 `实时: true`。事件统一用「变化」（值确认）与写入取同一时机，**不要混用**逐键 `onInput` 与"变化"两套时刻，否则状态会在"输一半"时被污染。

示例（一个表单 + 一个读它的按钮）：

```json
{
  "type": "界面",
  "标题": "记账",
  "子组件": [
    {
      "type": "表单",
      "输入": [
        { "type": "输入框", "标签": "金额", "变量": "金额" },
        { "type": "输入框", "标签": "备注", "变量": "备注" }
      ]
    },
    {
      "type": "按钮",
      "文字": "保存",
      "点击": {
        "事件名": "保存账单",
        "回调变量": ["金额", "备注"]
      }
    }
  ]
}
```

↑ 用户输入 `金额`/`备注` 后点"保存" → 事件 `保存账单` 收到字典 `{金额:…, 备注:…}`。

## 五、内置控件类型

以下为本规范的内置控件。**`type` 只用中文**；控件表（第七节）把这些中文 `type` 映射到对应控件实现（`.so`）。

### 1) 容器 / 布局（负责排列，职责通用，稳定）

| `type`（中文） | 作用 | 主要属性 |
|--------|------|----------|
| `界面` | 一屏的根容器 | `标题`，`子组件`，`主题` |
| `列` | 纵向堆叠 | `子组件`，`间距` |
| `行` | 横向排布 | `子组件`，`间距` |
| `卡片` | 卡片容器 | `子组件` |
| `表单` | 聚合一组输入控件 | `输入`（数组，每项为输入控件） |
| `分隔线` | 分隔线 | —— |
| `占位` | 占位 | `高度` / `宽度` |

### 2) 交互控件（有输入 / 有点击）

| `type`（中文） | 作用 | 事件属性 |
|--------|------|----------|
| `按钮` | 按钮 | `点击` |
| `输入框` | 单行输入 | `变化` |
| `多行输入` | 多行输入 | `变化` |
| `复选框` | 复选 | `变化` |
| `开关` | 开关 | `变化` |
| `单选组` | 单选组 | `变化` |
| `下拉` | 下拉选择 | `变化` |
| `标签组` | 标签组（单/多/展示） | `变化` |
| `滑块` | 滑块 | `变化` |

> 输入控件的「变化」仅指**值确认**（失焦/提交）时的事件；变量的实际写入时机见第四节规则 8。

### 3) 展示控件

| `type`（中文） | 作用 |
|--------|------|
| `文本` | 文本 |
| `图片` | 图片 |
| `图标` | 图标 |
| `指标` | 大号数值/指标 |
| `角标` | 角标/状态 |
| `列表` | 列表 |
| `表格` | 表格 |

### type 别名（兼容旧写法）

历史/英文写法作为"别名"接受，运行时经词典归一到上面的中文 `type`：

```
screen→界面  column→列  row→行  card→卡片  text→文本  image→图片  icon→图标
button→按钮  text_input→输入框  tarea→多行输入  checkbox→复选框  switch→开关
select→下拉  slider→滑块  list→列表  table→表格  ...
```

**新写的 `.vua` 一律用中文 `type`**；别名仅为保证旧文件可读，不建议再用（否则词典联想易打架）。

> 控件表里没有的内置控件，同样按"扩展控件"处理（见第十二节）——本规范不强制穷尽列表。

## 六、事件绑定

`.vua` 不写逻辑。事件**事件名**与**取值来源**都由 `.vua` 声明，运行时按名回调到 `.vus`：

1. **输入控件带 `变量`**：每个输入控件声明把当前值写入一个具名"变量"。表单状态即收集在这组变量里。
2. **事件声明 `事件名` + `回调变量`**：触发时把指定变量的值一并交给逻辑。

```json
{
  "type": "界面",
  "标题": "记账",
  "子组件": [
    {
      "type": "表单",
      "输入": [
        { "type": "输入框", "标签": "金额", "变量": "金额" },
        { "type": "输入框", "标签": "备注", "变量": "备注" }
      ]
    },
    {
      "type": "按钮",
      "文字": "保存",
      "点击": {
        "事件名": "保存账单",
        "回调变量": ["金额", "备注"]
      }
    }
  ]
}
```

按下 `保存` → 查 `.vus` 里的 `保存账单` 函数，并把当前变量 `金额`、`备注` 的值一并传入。

### 取值来源

- `变量`（输入控件）：声明"我写到哪个变量"。一个输入控件只写一个变量，值是它的当前输入。
- `回调变量`（事件控件）：声明"触发时把哪些变量的值带给逻辑"。可为空（纯事件通知）。

### 事件分发

```
用户点击 → Android View 触发
   → 取出该控件在 .vua 里声明的事件名（渲染时贴在控件上）
   → vua_触发事件(事件名, 回调变量取值字典)
       → 查"事件名 → 逻辑函数"登记表（.vus 侧提供）
           → 命中：调用，传入变量值字典
           → 未命中：报错"未找到处理器：<事件名>"
```

- `.vua` 渲染层只负责"点击 → 取出事件名 → 调 `vua_触发事件`"，不接触 `.vus` 内部。
- "事件名 → 函数"登记表由 `.vus` 逻辑侧提供（编译期生成静态表，或解释器维护符号表）。

## 七、JSON 控件表（中文 type → 控件 / .so）

控件表是一份 JSON，负责把 `.vua` 里的**中文 type** 映射到**承载它的控件依赖（.so）**。它是"可拓展"的登记处。

```json
{
  "控件表": {
    "按钮":   { "so": "libvua_基本.so" },
    "文本":   { "so": "libvua_基本.so" },
    "输入框": { "so": "libvua_基本.so" },
    "迷你图": { "so": "libvua_图表.so", "字段": { "数据": "value", "颜色": "color" } }
  }
}
```

- **`so` 表的键是权威中文 `type`**；英文别名（如 `button`）只在第五节的别名层被归一，不建议直接作为键。
- **一个 `.so` 可承载多个控件**（如上 `按钮/文本/输入框` 都在 `libvua_基本.so`）。
- `so` 字段：指向承载控件实现的依赖。APK 能读到它即可，不强求其内部形态（见第八节）。
- `字段`（可选）：控件自带字段词典，覆盖全局词典（见第九节）。

### 解析流程

```
遇到中文 type
   → 查控件表
       → 命中：定位到 .so → 加载 → 用该控件实现渲染
       → 未命中：字段词典无法翻译 → 直接报错（见第十节）
```

## 八、控件依赖（.so）约定 —— 只要求"能被读到"

**不强制规定 .so 的 ABI。** 只要满足以下两条，该控件依赖就能在 `.vua` 里被登记使用：

1. Android APK **能读到/能加载**它（`System.load` 或资源可访问）。
2. 在控件表里登记了一个中文 `type` 名。

控件内部是 JNI 方法、native 导出函数还是其他形式，**由控件自己决定**，本规范不设统一 ABI 门槛——避免给扩展设限。

> 诚实提醒：Android 自带的 View 控件（Button/TextView 等）是 Java/Kotlin 的 `View`（编译进 dex），**不以 .so 形式暴露为"按 type 可取用"的控件**。真正以 .so 形式提供、可即插即用控件的类目较少，多数需要一层薄适配，把 .so 的能力包成"能被 `type` 查到、字段词典对齐"的控件。本规范不隐瞒这一点，但**不阻止**这种形态存在。

### 最小扶手示例：如何把一个真实控件接进 `.vua`

以"按钮"为例，一条看得见、能照做的落地路径（Kotlin 包一层原生 View，不必碰 .so 的自绘 ABI）：

1. **写控件**：一个 Kotlin 类继承 `android.view.View`，读取 `.vua` 经词典翻译后的中文键（如 `文字`）设置显示、事件名（如 `点击`）；被点击时调 `vua_触发事件("按钮点击", {})`。
2. **打进 APK**：控件源码随 APK 打包（Kotlin 编进 dex；若走真正的 `.so`，则提供 JNI/导出入口让渲染器能调到这个 View）。APK 能读到它即可。
3. **登记控件表**：
   ```json
   { "按钮": { "so": "libvua_基本.so" } }
   ```
   （控件若直接在 dex 里，`so` 也可省去或以"进程内置"占位。）
4. **`.vua` 里直接用**：
   ```json
   { "type": "按钮", "文字": "保存", "点击": "保存进度" }
   ```

> 这条路径说明"扩展一个真实控件"有据可循：控件 = 一个"能被 APK 读到、能按 type 取到、属性/事件经词典对齐"的 View 实现。**先做 `文本`/`按钮` 两个控件**，即可验证整条「控件表 → 词典 → .vua → 触发事件」链路，其余控件照此复制。

## 九、字段词典（中文 ↔ 控件内部字段）

`.vua` 写中文属性名，控件内部可能有自己的字段名。二者靠**词典**翻译，查找顺序：

```
1. 控件自带字段词典（.vua 控件表里 `字段` 字段）→ 最优先
2. 全局词典文件（如 vua_dict.json，一份可编辑文件）→ 默认兜底
3. 都没有 → 报"未知字段"错误
```

- **全局词典只是一份文件**，不是写死在代码里。要改词、加词，直接编辑该文件即可，零代码改动。
- 扩展控件想自定义中文名，在自己的 `字段` 里加词典即可覆盖默认。

示例（全局词典文件 `vua_dict.json`）：

```json
{
  "词典": {
    "文字": "label",
    "内容": "value",
    "样式": "style",
    "提示": "placeholder",
    "子组件": "children",
    "点击": "onClick",
    "变化": "onChange"
  }
}
```

## 十、错误处理

**原则：直接报错，不静默降级。** 避免用户看到"界面没反应却不知道为什么"。

| 情形 | 行为 |
|------|------|
| `.vua` 里出现控件表中没有的 `type` | 报错："未找到控件 `<type>` 的映射"，并列出现有可用控件 |
| `.vua` 属性在词典里查不到 | 报错："未知字段 `<属性>`"，提示可用的词典键 |
| `.vua` JSON 语法错误 | 报错并指出文件 / 位置 |
| 控件引用的 `.so` 无法被 APK 读到 | 报错："控件 `<type>` 的依赖 `xxx.so` 不可用" |

## 十一、离线校验（vua lint）

错误不应等装机后才发现。草案期提供一个**离线**校验工具 `vus lint`，在**改 `.vua` 时**就把问题拦下来，静态（无运行时）读取 `.vua` + 控件表 + 词典 + `.vus` 符号进行检查：

| 检查项 | 说明 |
|--------|------|
| `type` 在控件表 | 每个 `type` 必须是控件表中的中文 `type`（可归一的别名按第五节处理） |
| 字段在词典 | 每个属性名都要能经词典翻译成控件内部字段（控件自带词典 > 全局词典） |
| 事件名绑上函数 | 每个事件属性里的 `事件名` 都能在 `.vus` 里找到对应的逻辑函数（.vus 侧导出符号） |
| JSON 语法 | `.vua` 是合法 JSON |
| 引用控件存在 | 控件表里的 `.so` 在打包清单里存在 |

用法（草案预期）：

```
vus lint 主界面.vua --dict vua_dict.json --符号 main.vus.sym
```

产出：逐条错误（`文件:行:列` + 原因 + 建议），不产生副作用。把"保存时就知道"，提前到"装机之前"。

## 十二、可拓展流程

**加一个新控件：**
1. 把控件实现放进一个能被打进 APK 的控件依赖（.so）。
2. 在 JSON 控件表里登记一行：`中文type → 该 .so`（需要时加 `字段` 词典）。
3. 重新打包 APK 一次（控件入库）。
4. 之后 `.vua` 里即可用它，后续换界面**不再重打包**。

**加一个字段 / 改字段名：**
- 编辑全局词典文件，或在该控件的 `字段` 里补充——不碰解析器、不碰代码。

## 附录：借鉴说明

`.vua` 的**解析思路**借鉴自 [Kai 9000](https://github.com/SimonSchubert/Kai)（SimonSchubert）的 kai-ui 组件树机制（JSON 组件 DSL + 运行时解析）。

- 两者协议/目的不同：kai-ui 是"LLM 实时生成的宽容 JSON"（容错解析优先）；`.vua` 是"开发者手写的确定性界面声明"（**严格解析、直接报错**优先）。因此 `.vua` **不采用** kai-ui 的容错/降级策略，改为第十节的严格报错。
- 仅借鉴"JSON 组件树 + 运行时解析 + 事件回调闭环"这一**思路**；`.vua` 的属性命名（中文）、控件表与词典机制、严格错误处理均为 VUS 自身的原创设计。
