# VUS 特点与优点 —— 以「安卓计算器 APK」为例

> 对象：VUS 语言作者
> 来源：用 VUS（VUA 组件流）开发安卓计算器 APK（含历史记录、双 ABI、JNI 桥、手工构建链）的完整过程
> 定位：与《VUS 开发体验反馈-安卓计算器APK.md》互补，本文聚焦 VUS 的差异化特点与优点
> 结论先行：VUS 用中文把「逻辑 + 声明式 UI + 平台桥」统一成一套可编译为 C 的语言，以编译期严谨性和 JSON 全栈统一，换来极小的运行时和极高的可移植性

---

## 一、差异化定位：给中文开发者的一门"领域语言"

### 1.1 中文原生语法，零门槛

`定义 / 如果 / 否则 / 当循环 / 返回 / 结束`、`界面_取 / 界面_设置 / 文本_分割 / JSON_解析`——对中文开发者来说，读代码就是读业务，没有"英文关键字 → 中文心智"的翻译层。`calc.vus` 里连函数名都直接用中文（`事件_按数字`），整个计算器逻辑就像一份可执行的伪代码。

### 1.2 编译到 ANSI C，而非解释执行

`.vus` 直接生成 C（编译器把中文标识符编码成 UTF-8 的 C 符号名，如 `计算` → `vus__8BA1_7B97`），意味着：

- 没有 JVM / 解释器 / GC 开销，381K 的 APK 里就装下了完整应用 + 双 ABI 原生库；
- 天然可嵌入任意 C 生态——安卓端走 NDK 编译，桌面端同源码直接 `cc` 编译就能跑同样的逻辑做调试，一套 `.vus` 逻辑在两种环境复用。

### 1.3 JSON 是全栈统一数据格式

`.vua` 界面是 JSON，渲染树是 JSON，事件参数是 JSON，native 与 Java 的 JNI 交换还是 JSON。数据从界面声明到事件回传全程一个格式，无跨语言类型映射的阻抗。`文本_分割` 返回 JSON 数组字符串、`JSON_解析` 一等公民——语言把"数据结构"直接建立在 JSON 上，这在脚本语言里很少见，和 VUA 的 JSON 渲染树天然咬合。

---

## 二、VUA 组件流：声明式 UI + 事件驱动

### 2.1 界面与逻辑彻底分离

`vua_calc.vua` 只声明"长什么样"（显示区 / 历史区 / 按钮网格），`calc.vus` 只管"怎么算"。事件通过 `界面_绑定("按数字", 事件_按数字)` 在运行期绑定，同一份 `.vua` 可以挂不同逻辑，UI 和业务可以独立演进。

### 2.2 渲染树 + 指纹增量协议（设计亮点）

native 把 `.vua` 归一化成渲染树 JSON，用"内容指纹 + 屏序号 + View diff"决定 Java 端动作：

| 场景 | 动作 |
|------|------|
| 指纹与当前相同 | 零工作量 |
| 同屏（屏序号不变） | 只 `setText` 变化的变量文本（View diff） |
| 换屏 + 内容未变 | 命中 LRU 页面 View 缓存 |
| 其余 | 整树 JSON 解析构建 |

一次点击后计算器只更新 `显示` 那个 TextView，而不是整树重建。这个"版本号协议"其实是一个轻量级虚拟 DOM diff，比 Android 侧每次全量 `setContentView` 优雅得多。

### 2.3 状态字典模式简单可靠

全部状态放 VuaSession 字典（字符串键值），`界面_取 / 界面_设置` 读写。这个模式让状态有了**唯一真源**——跨屏、跨事件、跨语言（native ↔ Java）共享同一份状态，不依赖任何隐式变量作用域，行为可预测、可 dump（开发中靠 dump 渲染树就能直接看到 `显示: "0"→"7"` 的变化）。

---

## 三、工程化：小而实的运行时 + 可移植桥

### 3.1 运行时很小、平台桥干净

`vua.c + libvus_rt.c + vus_coro.c` 是全部运行时，加上一个协程库支撑并发。新平台 = 写一个桥：安卓是 `jni_bridge.c` + `VuaBridge.callJava`（VUS 内建 → Java 能力），X11 是画布流。平台能力以"桥"的方式暴露给语言内建，扩展新平台不需要改语言本身。

### 3.2 `vus build --apk` 一步出安卓工程

一条命令就生成 `AndroidManifest.xml`、Java 壳、JNI 桥、Android.mk 整个工程骨架——构建链本身还有脆弱点（见反馈文档），但"从 `.vus` 到可签名 APK"这条路的自动化程度已经很高，这是它能落地安卓的关键。

### 3.3 全文本可读、可 diff、可版本管理

界面是 JSON、逻辑是文本、产物是标准 APK，整个项目没有任何黑盒二进制格式，git 协作和 review 体验好。

---

## 四、一句话总结

VUS 的差异化在于：**用中文把"逻辑 + 声明式 UI + 平台桥"统一成一套可编译为 C 的语言**——它不追求通用语言的覆盖面，而是瞄准"中文开发者快速产出跨平台小应用"这个场景，用编译期严谨性和 JSON 全栈统一换来了极小的运行时和极高的可移植性。计算器这个例子证明了这条路是通的：一份中文源码，桌面能测、安卓能装、双 ABI 能跑。
