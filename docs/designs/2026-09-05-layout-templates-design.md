# VUS 页面布局模板 —— 设计文档（.vaz 声明式布局 + 后续抽屉控件）

日期：2026-09-05
状态：方案设计（待实现）
相关批次：承接《VUS开发体验反馈-VUS文档APK.md》2.3 资源/能力边界检查，由「VUS 文档 APK」实战暴露的通用布局需求引出；与既有 `.vaz` 扩展包机制（PLUGIN_USAGE.md §六）同源。

## 1. 背景与目标

### 1.1 为什么需要布局模板

VUA 组件流目前的布局控件只有 `列 / 行 / 卡片 / 表单`（LinearLayout 族）。真实应用常见的页面骨架（侧边栏、顶栏、宫格导航、分组列表）没有现成形态，每个开发者都要自己拼一遍：

- **侧边栏**：左导航列 + 右主内容，内容随导航切换；
- **顶栏**：标题栏 + 动作按钮 + 内容区；
- **宫格导航**：图标 + 文字的网格入口；
- **分组列表**：带节标题的长列表。

目标：提供**声明式、可复用**的布局模板，开发者一行引用、传入菜单/内容即得整页骨架，不用每次手拼结构。

### 1.2 落地原则

1. **能模板化的不碰渲染器**：静态骨架用 `.vaz` 构建期展开实现（机制现成），渲染器零改动；
2. **真交互才走渲染器**：可滑动收起的抽屉（Drawer）作为后续渲染器控件能力单列，与模板互补；
3. **模板与普通控件同构**：展开后即为标准 `行/列/卡片/按钮/文本` 组件树，走既有渲染/事件链路。

## 2. 机制：复用 `.vaz` 复合控件模板

`.vaz` 已有构建期展开能力（`vus vaz expand 页面目录 -v 包.vaz`）：

- 模板文件格式（见 `testdata/vaz/common-controls/controls/search_bar.json`）：

```json
{
  "中文名": "搜索条",
  "英文名": "searchbar",
  "模板": { "type": "行", "子组件": [ ... 用 {参数} 占位 ... ] }
}
```

- 展开后复合控件被替换为组合组件 + 逻辑片段，再走 VUA 正常渲染/事件链路。

布局模板沿用同一格式，新增 **结构占位符**（见 §3.2）。

## 3. 布局模板定义

### 3.1 侧边栏布局（核心示例）

`templates/sidebar.json`：

```json
{
  "中文名": "侧边栏布局",
  "英文名": "sidebar",
  "模板": {
    "type": "行",
    "子组件": [
      { "type": "列", "宽度": "{宽度}", "样式": "{菜单样式}", "子组件": "{菜单}" },
      { "type": "卡片", "权重": 1, "子组件": "{内容}" }
    ]
  }
}
```

使用（`.vua`）：

```json
{
  "type": "侧边栏布局", "宽度": 180, "菜单样式": "menu",
  "菜单": [
    { "type": "按钮", "文字": "概览", "事件": { "事件名": "切页" } },
    { "type": "按钮", "文字": "文档", "事件": { "事件名": "切页" } }
  ],
  "内容": [ { "type": "文本", "内容": "主区" } ]
}
```

展开后 = `行(列(菜单按钮们), 卡片(主区))` → 正常渲染。菜单点击触发 `切页` 事件，主区内容由 `.vus` 用 `界面_显示_JSON` 重绘。

### 3.2 结构占位符（开放问题 1，需扩展 vaz 展开器）

现有 `search_bar.json` 的占位符只出现在**字符串/变量**位置（`"{id}_关键词"`、`"{variable}"`），而布局模板需要在**子组件数组整体位置**插入 `{菜单}` / `{内容}`。需要 vaz 展开器支持：

- 占位符出现在 `子组件`（数组）位置时，按结构整体插入（数组或单节点）；
- 缺省值：模板可声明 `"默认": { "宽度": 180, ... }`，调用方未传时用默认。

### 3.3 第一批模板清单

| 模板 | 展开结构 | 关键参数 | 备注 |
|------|----------|----------|------|
| 侧边栏布局 | 行(列菜单, 卡片主区) | 菜单 / 内容 / 宽度 / 菜单样式 | 本设计核心示例 |
| 顶栏布局 | 列(顶栏, 内容) | 标题 / 动作按钮 / 内容 | 顶栏含返回按钮位 |
| 宫格导航 | 行×列 网格(图+文) | 项们 / 列数 | 复用 列表/表格 或行×列拼装 |
| 分组列表 | 列表 + 节标题 | 分组数据 | 列表控件已有「加载更多」可叠加 |

## 4. 真抽屉控件（已落地 2026-09-05，渲染器能力，独立于模板）

静态侧栏模板覆盖"骨架"需求；需要**滑出/收起交互**时用下面已实现的渲染器控件：

- 控件表登记 `侧边栏`：字段 `菜单` / `内容` / `事件`（菜单项点击，携带 下标/值，与列表一致）/ `宽度` / `侧`（左/右）；
- `VuaRenderer`：Android `DrawerLayout` + 菜单面板 + 主内容；
- 与模板关系：模板 = 零成本静态侧栏；控件 = 交互抽屉，按需选用。

## 5. 验证方案

1. **展开冒烟**：`vus vaz expand` 把含 `侧边栏布局` 的页面展开为标准组件树，断言结构正确；
2. **桌面冒烟**：`.vus` 驱动 `界面_显示_JSON` 渲染展开结果，事件（切页）可触发；
3. **APK 实测**：将「VUS 文档 APK」首页改造为侧边栏布局（左：文档分类导航；右：文档列表/详情），真实场景验证；
4. **回归**：现有 `vaz_import_demo.vus` / `vua_home.vua` 用例不受影响。

## 6. 开放问题

1. **结构占位符**：vaz 展开器目前仅支持字符串/变量替换，需扩展支持 `子组件` 整体结构插入与默认值（§3.2）；
2. **样式传递**：菜单列的底色/高亮等样式如何传——`菜单样式` 键 or 直接透传属性；
3. **默认参数**：宽度等是否声明默认值（如 180dp）；
4. **模板嵌套**：布局模板内能否再引用其他模板（如侧边栏内容里放顶栏），展开器递归深度与循环引用防护；
5. **真抽屉时序**：抽屉控件是否与模板同批实现，还是模板先行、抽屉后续（建议模板先行）。
